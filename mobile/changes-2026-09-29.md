# Changes 2026-09-29

## Fixed: map mountain hidden behind the sky (`MapScreen.tsx`)

**Report:** on-device, the mountain range looked cut off by a flat horizontal
line, as if the blue sky sat in front of it hiding its body; clouds sat over
the peaks instead of on the sky.

**Root cause:** since 2026-08-03 the mountain's top edge was tied to
`hudHeight` (measured height of the streak/XP/search overlay) and clipped
there. It was invisible while the HUD was short, but every time the search
button grew (64 -> 96px on 09-22, 2x on 09-29) the HUD got taller and more of
the mountain was sliced off with a flat line. `SKY_CLOUDS` also rendered after
the mountain in JSX, so clouds drew over the peaks.

**Fix:**
- Mountain no longer depends on `hudHeight`. It renders at
  `mountains_crop.png`'s own 1400x385 aspect (`MOUNTAIN_H = MAP_W * 385/1400`),
  bottom-anchored at `SKY_BOUNDARY_Y + sc(28)` so the grass still overlaps its
  base. Full silhouette always visible.
- `opacity: 0.9` removed from the mountain (sky was bleeding through the rock).
- `SKY_CLOUDS` moved to render before the mountain, so they sit on the sky.
- `hudHeight` state and the HUD `onLayout` removed (no longer used).

## Changed: search button (`MapScreen.tsx`)

- 2x its previous size (`streakPillWidth * 2`), per request.
- Centered exactly under the streak pill via a pill-width wrapper with
  `alignItems: 'center'`; the streak pill's own position is unchanged.

## Added: Progress button + per-surah progress screen

- **Map HUD:** new Progress button (SVG shield, `components/ShieldIcon.tsx`)
  in a right column under the XP pill, parallel to the search button. It is
  sized to the search art's visible square (45 of the 91px canvas) and starts
  at the same height. XP pill position unchanged.
- **`SurahProgressScreen`** (route `SurahProgress`): summary card (surahs
  complete, levels done, overall bar), sections In progress / Completed / Not
  started, animated bar per surah, pull to refresh, refetch on focus. Tapping
  a row jumps the map to that surah, straight to its next unfinished level if
  started (`Map` params gained `jumpToGroupId`/`jumpToLevelIdx`;
  `jumpToSurahStart` takes an optional target level).
- **Data (`utils/surahProgress.ts`), real only, no backend change:** one
  batched `first-levels` call for all 114. Completions are only written by
  finishing a level and levels unlock in order, so a surah whose first level
  isn't completed has 0 completions; only surahs with a completed first level
  get a `levels(n)` call (4 at a time). Totals come from the same formula as
  the map's `buildLevelsWithReviews`. If the backend's level count disagrees,
  the surah shows "Progress unavailable right now" instead of a guessed
  number (currently Al-Baqarah: `list_lesson_groups` still caps at 200 of 215).
- **Jump fix (pre-existing bug, surfaced here):** the pending-jump effect
  looks the target up by real `groupId`, but right after a chapter switch
  nodes don't carry real ids yet, so it fell back to the surah's FIRST level
  and cleared the jump. The fallback now uses the target's position
  (`levelIdx`), so "continue" from Progress lands on the next level.
- Copy: "1 level" singular; percentages never show 0% for real progress
  (`<1%`) or 100% for unfinished work (`99%`).
- Verified on the Pixel_5 emulator with a real completion: finished
  Al-Kawthar level 1 on a fresh guest; Progress then showed it under In
  progress at 1 of 3 levels, 33%.
- HUD containers now `pointerEvents="box-none"` so a drag starting on empty
  sky between the buttons scrolls the map instead of being swallowed.

## Changed: stars follow accuracy (100% = 3, 66%+ = 2, finished = 1)

- New `utils/stars.ts`: `starsFromAccuracy` (thresholds above, min 1 for a
  finished level) and `levelStars` (map: derived from the level's saved best
  `score_pct`, falling back to stored `stars` only if the score is missing).
  Old thresholds were 90/60.
- `LessonSessionScreen` uses the shared function (its local copy removed).
- `MapScreen` node stars now come from `levelStars`, so levels finished
  before this change also show the new count, with no backend backfill.
- `LessonSummaryScreen` heading ("Excellent!"/"Great job!"/...) now uses the
  same tiers, so 95% no longer says "Excellent!" beside 2 stars.
- Help text updated to describe the new rule.
- Backend `_stars_from_score` still uses 90/60: prompt given to the user so
  stored stars match.

## Fixed: wrong answers not lowering accuracy (user finished at 100% after mistakes)

- **App cause:** `LessonSessionScreen` computed accuracy as
  `correct / (correct + mistakes)`, where `mistakes` is the HEARTS counter.
  Hearts skip `mistakes_review`, `remediation_up` and every exercise on a
  review (special) level, so wrong answers there never counted: a review
  level always scored 100%. A resumed session also divided by
  `hearts_lost_half` (heart units, not answers).
- **App fix:** new `accuracyRef`, separate from hearts, taken from the
  backend's `correct_count`/`wrong_count` on every answer (fallback: local
  tally of graded, non-skipped attempts). Resume seeds it from the session's
  `correct_count`/`wrong_count` (`lessonStore` gained `wrongCount`).
- **Backend fix (edited in ustadAppBackend, NOT committed or deployed; user
  owns that):** `session_engine.process_answer` now counts every graded
  attempt in every phase and source (was main + review, formula only). New
  tests added; full suite 213 passed. Until it's deployed, remediation-phase
  wrong answers still won't count, but review-level and main-phase ones will.

## Changed: straight grass edge under the mountain

- `GRASS_EDGE_D` is now a straight line at `SKY_BOUNDARY_Y` (was a
  hash-seeded jagged "torn" edge). The mountain's base extends `sc(28)` below
  it and the grass draws on top, so no sky shows between them.
- Asset finding: `mountains_crop.png` is one central peak (top at row 17 of
  385 at x=700) tapering to nothing at both ends (no mountain at x < 17;
  x=50 is only 22px tall), which is why it looks big in the middle and tiny
  at the sides, with sky reaching the grass at the edges. The user will
  supply an edited full-width range: straight, fully opaque base across the
  entire width, no grass, transparent above. Not built yet; waiting for it.

## Fixed: mountain and grass always meet (2026-09-30)

- `mountains_crop.png` (same file, overwritten): cropped the 17 empty
  columns on the left so the bottom row is solid edge to edge (1382x385),
  then repeated that bottom row 40 more rows down as a solid skirt
  (now 1382x425). Silhouette unchanged.
- `MapScreen`: aspect and skirt size read from the asset
  (`Image.resolveAssetSource`); the art's base sits exactly on the grass
  line, the skirt (~11dp) goes under it, so rounding can't open a gap.
- Grass tile Svg: `preserveAspectRatio="none"` (default "meet" shrank the
  tall tile by a sub-pixel width mismatch and pushed the grass edge ~2dp
  down, opening a sky line), and 2dp wider than the canvas (its bitmap
  rounds down, leaving a 2px strip at the right edge). Grass path overshoots
  both sides.
- Build trap: an asset-only change shipped the OLD image while the bundle
  had the new dimensions (stretched art). Fix was deleting
  `android/app/build/generated/res/react`, `intermediates/merged_res`,
  `merged-not-compiled-resources`, `packaged_res` and `%TEMP%/metro-cache`,
  then verifying the image size inside the APK.
- Verified on the emulator: every column scanned, no sky within 2px of the
  seam (only the waterfall's own white), both corners clean.
