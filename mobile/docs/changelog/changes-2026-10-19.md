# Changes, 2026-10-19

## Tour offer never wired to Map2Screen (never actually started for real users)

Reported after build 20051 was already queued ("last time i used app i didnt
see it"): the "want a tour?" offer — `TourOfferModal`, the `offerVisible`/
`setOfferVisible`/`start` tour-store wiring, `wasTourOffered`/`setTourOffered`
from `utils/storage` — only ever existed in `MapScreen.tsx` and the dev-only
`MapScreenV2.tsx`. When Map2Screen became Home (2026-10-16, see that date's
changes.md), this wiring was never ported over, so the tour had no entry
point on the screen real users actually land on — independent of, and a
bigger gap than, the spotlight-targeting work done on it earlier today. Fixed
by porting the same offer logic into `Map2Screen.tsx`: offered once, gated on
`loadingPaths` finishing and `wasTourOffered()` being false, `TourOfferModal`
rendered alongside the screen's other modals.

## ScrollView missing `flex: 1` on Profile and Leaderboard

Reported: Profile's bottom rows (About section, Logout, Delete Account,
version) overlapped the custom Figma tab bar instead of stopping above it —
"the bar is placed ON the original UI." Root cause: both screens' `<ScrollView>`
had no `style={{ flex: 1 }}`, so the ScrollView sized to its own content
instead of filling its already-correctly-bounded parent, and — since RN's
default `overflow` is `visible`, not `hidden` — the oversized, unclipped
content bled past the screen's own bottom edge into the same region the tab
bar paints, which is where the "dark line above the tabs" the user later
reported on Leaderboard came from too (same bug, surfaced because Leaderboard
can have enough rows to overflow). Fixed both: `ProfileScreen.tsx`,
`LeaderboardScreen.tsx`.

## Playcard redesign (Figma `Landing-Page` file, node 1090:4964) + positioning fix

User's two asks: reskin the level start/repeat card to match a new Figma
frame, and fix a separate bug where the card rendered parallel to (sometimes
overlapping) the node it describes.

- `LevelActionCard.tsx` / `mapStyles.ts` / `mapModel.ts`: solid green card
  (`colors.levelStartAccent`), Luma mascot art, a bottom-shadow "pressed"
  button (outer rect in `levelStartAccentShadow` as the lip, white face inset
  from the bottom so the lip shows as a flat strip — RN shadow props can't
  draw a flat offset shadow directly). No close button, matching the Figma
  frame; dismissal is a tap elsewhere on the map instead (see below). Button
  copy kept exactly as before ("START A NEW LEVEL" / "REPEAT THE LESSON") —
  user's call, reuse the existing copy rather than the frame's "CONTINUE".
  `ACTION_CARD_ASPECT` updated to the new frame's 180:309 ratio.
- `Map2Screen.tsx`: the card's `top` used to be the node's own centre y minus
  half the card's height — i.e. always vertically centred ON the node by
  construction, which is what the horizontal-only dodge logic was fighting
  and losing. Now computed from the node's top edge minus the card's height
  minus a margin, so the card sits in the empty space above the node; falls
  back to below the node only when there isn't room above within the current
  band (user's call on that edge case).
- `Map2Band.tsx`: added `onBackgroundPress`, wired only on the band holding
  an open card — its root becomes a `Pressable` calling the existing
  `dismissActionCards`; every other band, and the card's own nested
  touchables, are unaffected (a parent `Pressable`'s `onPress` never fires
  for a tap a child already claimed).
- `MapScreen.tsx` (dead, unrouted since the map2 switch, confirmed via
  import-site grep): its two `LevelActionCard` call sites still passed the
  now-removed `onDismiss` prop, which would have failed `tsc`. Removed, no
  behavior to verify since the screen is unreachable.

## Guided tour rebuilt for the Map2 / 5-tab redesign

The tour (`tourStore.ts`, `TourOverlay.tsx`, `tourSteps.ts`) was already
fully built and is genuinely good — but its tab/HUD targets were never wired
to anything in the Map2 redesign (no `useTourTarget` call existed in
`Map2BottomBar.tsx` or `Map2Header.tsx`), so those steps silently fell back to
a centered card with no spotlight. The lesson half (`TourLessonScreen.tsx`)
needed no changes: it renders the real `LessonHeader`/exercise components
directly, not a mock, so it was already correct for the current hint/hearts/
progress/check/mic/feedback UI.

- `tourSteps.ts`: new `tabBuilding` step between Quests and Board — "Prayers"
  / "You can log your prayers here" (user's copy). 20 steps total now.
- `Map2BottomBar.tsx`: all 5 tab icons wired via `useTourTarget`, one hook
  call per fixed key at the top level (Rules of Hooks — can't call it inside
  the `ITEMS.map()` loop), looked up per item instead.
- `Map2Header.tsx`: Streak and XP stat cards wired the same way
  (`hudStreak`/`hudXp`).
- `StatCard.tsx`: added `targetRef` prop, forwarded to whichever of
  `View`/`TouchableOpacity` it renders.

## Gems and Hearts explainer pages

New, modeled on `XPScreen.tsx`'s layout: `GemsScreen.tsx`, `HeartsScreen.tsx`,
both registered in `RootNavigator.tsx` (modal presentation, like XP/Streak)
and reachable by tapping the Hearts/Gems pills on the map HUD
(`Map2Header.tsx`: `onHearts`/`onGems`, not guest-gated like Streak/XP since
these are explainers, not account data).

- Gems: explains it as a separate, spendable currency (e.g. to buy XP), not
  live yet. Iterated twice on user feedback: first pass had a "Coming soon"
  card and a Lumo mascot hero — removed the Coming soon card, and replaced
  the mascot with the real gem icon (`MAP2_IMAGES.gems`/`stat_gems.png`),
  the same art the HUD pill uses. The badge's placeholder was initially a
  "—" (em dash) for the non-existent balance; this app has a standing
  no-dash-in-copy rule, so it's now a plain "Not live yet" label with no
  number at all.
- Hearts: explains the real per-lesson mechanic (`LessonHeader.tsx`'s
  `MAX_HEARTS = 5` / `MAX_MISTAKES = 10`) — 5 hearts shown, each worth two
  half-heart "chances," so 10 mistakes before a level ends and restarts free.
  Includes the full → half → empty visualization the user asked for, using
  the same three heart images (`redh`/`halfh`/`whiteh.png`) `LessonHeader`
  itself uses, not redrawn art.
- `colors.ts`: added `levelStartAccentShadow`, `redBorder`, `blueBorder` for
  the above.
