## Google Sign-In — RESOLVED

Confirmed working live by the user on the already-installed Play Store app
(v1.0.16), no reinstall needed. Root cause and full fix history moved into
memory (`project_handoff_0825_google_signin.md`, RESOLVED section) rather
than duplicated here — short version: Play App Signing's certificate had its
SHA-256 registered in Firebase but never its SHA-1, and Google Sign-In's
Android OAuth client is SHA-1-keyed. Added the missing SHA-1 fingerprint in
Firebase Console. No app code change was the actual fix — the diagnostic
patch (`patches/@react-native-google-signin+google-signin+16.1.4.patch`) is
what made the real error message visible via logcat, which is what led to
pulling the real Play-delivered APK's certificate and finding the gap.

## Tab bar dead space — corrected further

`MainTabs.tsx`'s `TAB_BAR_PAD_BOTTOM_NO_INSET` was set to `8` (a "symmetric,
intentional-looking" compromise) in the 08-28 padding fix. User reported it
live, still visibly wrong. Changed to `0` — when there is genuinely no system
inset to clear, there is nothing to pad for; any nonzero compromise here is
the same category of bug, just smaller.

## HearAndSelect audio bug — real root cause found (was misdiagnosed once)

Reported: holding options in "hear the sound and select" produced no audio,
and the play/pause button flickered. The 08-28 `onLongPress` removal (a real,
separate fix for tap reliability) did NOT fix this — user confirmed live.

Actual cause: `HearAndSelect`'s `onPlayingChange` subscription bumped
`seqGenRef` on every between-word gap in a multi-word phrase, not just a
genuine external stop. The multi-word playback loop checks that same counter
to decide whether to continue — so after word 1 finished, the handler fired,
bumped the counter, and the loop saw a mismatch and quietly exited. Every
word after the first never played, and the button flipped to idle at the
same moment. Removed the subscription entirely (see the block's own comment
in `LessonSessionScreen.tsx`) — it's safe to remove now because the 08-28
`playToken` fix already covers the one case the subscription genuinely
existed for (Check pressed mid-phrase: stopAudio() bumps playToken, so every
remaining queued clip resolves near-instantly instead of hanging).

Flagged, not fixed: `PlayPauseBtn`/`SegmentPlayBtn` have a milder version of
the same class of bug (icon flickers mid-sequence, audio doesn't actually
drop, since `playUrlSequence` doesn't share this same counter). Not reported,
not touched.

## Map node status — disk-cache race on lesson completion

Reported: opening the app cold showed a node as locked/incomplete even
though it had genuinely been finished; the "Continue here" tag pointed at
the correct (but visually-locked) node. Pull-to-refresh fixed both at once,
which is what pointed at a cache issue rather than a logic bug.

Root cause: `bootCache.invalidateLevels()` (called on lesson completion)
clears both an in-memory cache (instant) and a 15-minute disk cache
(`AsyncStorage`, async) — but the disk clear was `void`'d, never awaited.
Finishing a lesson and closing the app shortly after (completely normal
usage) could outrun that write; if the process was suspended before it
landed, the stale disk snapshot survived into the next cold start.

Fixed: `invalidateLevels()` is now `async` and awaits the disk clear;
`lessonStore.completeSession()` now `await`s it. The full chain
(screen → completeSession → invalidateLevels → disk write) is sequenced
end to end before the app can navigate away from a completed lesson.
