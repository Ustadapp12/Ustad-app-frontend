# Changes, 2026-10-15

## New Figma day map ("Map2"), dev preview only

Built from Figma file `Zuu6uvLzDNTU2Ximzo80nr`, node `1047:1651` (440pt day
frame). Kept completely separate from the current map, per the user: nothing
in `MapScreen.tsx`, `MapScreenV2.tsx` or `screens/home/map/` was edited. It
is reachable only from a new `__DEV__` "M2" button above the existing "V2"
button, and its route and screen modules use the same guarded `require` as
MapV2, so none of it loads in a release build.

Layout follows the Figma frame: sky, sun and hill are pinned at the top and
the sand, path and nodes scroll underneath them. Progress climbs **upward**
(completed nodes below START, future nodes toward the hill), the reverse of
the current map. Everything is authored in Figma points and scaled by
`screenWidth / 440`.

Node art per level state (user's mapping): normal locked = lock, normal open
= trophy, current = book (drawn white on the green node) with the yellow ring
and START, review locked = chest (no pill), review open = camera, completed
= gold star with the star row, next surah's first level = "JUMP HERE?". The
ring is the share of the current surah's levels completed, from backend data
only. Top buttons: Search opens Search Surahs, the upper shield opens Surah
Progress (it keeps the Figma label "Review" for now), and Journey plus the
lower shield open "Coming soon". Bottom bar: chest opens Quests, trophy opens
Leaderboard, person opens Profile, the 8-point star does nothing yet, and
home scrolls to the current node.

What it reuses unchanged: `useMapData`, `useRecommendedJump`,
`createLevelLaunchHandlers`, `useStreakFrozenPopup`, the chapter/level model
in `mapModel.ts`, `LevelActionCard`, `LumaFloat`, `LoadingBar`, and the
existing modals. Moving forward a chapter lands at the bottom of the new
chapter, and moving back lands at its top.

Performance choices:
- Background is a flat colour (`#FAF1D9`), not an image. The Figma
  "background" export turned out to be a single solid fill, not a gradient.
- The dotted path is about 110 small rotated Views per chapter, not one tall
  Svg (a full-height Svg would be a roughly 35MB Android bitmap).
- Node faces and lips are plain Views. The Figma drop-shadow filters are
  reproduced as solid lips, so no Svg filters are used.
- No continuous animations. The only animations are the short locked-node
  shake and the existing level card's spring. No scroll listener.

Files:
- `src/screens/home/map2/` with `Map2Screen.tsx`, `map2Model.ts` (layout),
  `map2Theme.ts`, `styles.ts`, `assets.ts`, `useEnrichedSections.ts`,
  `components/` (header, stat card, feature button, node, ring, star row,
  label, path, decor, surah board, bottom bar, feedback button) and `art/`
  (26 components generated from the SVGs, with every path verified verbatim
  against the source files). Each art component takes an optional `fills`
  prop that swaps source colours. Regenerate with
  `figma_Designs/map2_originals/svg2tsx.py <assets/map2_assets> <src/screens/home/map2/art>`,
  which overwrites `art/`.
- `useEnrichedSections.ts` copies MapScreen's node enrichment, active-node
  and full-levels backfill rules (including "never show completed or stars
  without backend data"). It is a copy, not an extraction, so MapScreen stays
  untouched. The duplicate goes away when map2 replaces MapScreen.
- `src/screens/comingSoon/ComingSoonScreen.tsx`, opened by Journey and Review.
- `navigation/types.ts`, `RootNavigator.tsx`, `MainTabs.tsx`: dev-only
  routes `Map2` and `ComingSoon`, plus the "M2" dev button.

Assets: `assets/map2_assets/` holds 33 files, renamed to what they are
(`icon_lock.svg`, `nav_home.svg`, `stat_streak.png`, and so on). The 7 PNGs
were 1024px (1.9MB) and are resized to 192px (139KB). Originals and the
reference-only SVGs are in `figma_Designs/map2_originals/`, outside the app.

Verified: `tsc` clean, eslint has 0 errors, the existing 56 jest tests pass,
and a throwaway layout test was run across all 158 chapters × 3 widths × 4
current-node positions (0 board/node overlaps, grass never on a node,
bottom-up order, and the larger gap above START). A static render of the
layout with the real art was compared against the Figma frame. **Not yet run
on a device.**

## Map2, second pass: continuous map and fixes from the user's screenshot

**No more chapters in map2 (user's call).** The whole Quran is one scroll,
An-Nas at the bottom climbing to Al-Fatihah. Chapters existed because the
old map's road was tall Svg tiles (Android bitmap crashes). Map2 has none,
so:
- `map2Model.ts` lays out all 4,744 levels as plain numbers (about 1ms).
  The map is cut into fixed-height bands of 1600pt, and `bandContent()`
  builds a band's dashes, decor and boards only when the list renders it.
- `Map2Screen` is a FlatList of bands with `getItemLayout`, `windowSize` 5
  and `removeClippedSubviews` off (labels hang past band edges). A band holds
  at most 18 levels.
- Level data is fetched for surahs as their bands come into view
  (`onViewableItemsChanged` -> `fetchPhase`), and the full-levels backfill
  only covers on-screen surahs plus the recommended one.
- `useMap2Jump.ts` replaces the chapter-based `useRecommendedJump` for map2:
  land on the active level, follow it after a lesson, jump to a surah. Map2
  no longer uses `useRecommendedJump`.
- Next stage / Previous stage pills are gone.

Checked across 3 widths and 5 active-level positions: every level is in
exactly one band, there are no signboard/node or signboard/Lumo overlaps
across all 114 signs, and no grass sits on a node.

Fixes and changes:
- The header no longer clips its contents, which had cut the Journey and
  Review labels. A 28pt fade under the hill replaces the hard edge nodes
  were cut by.
- Stat icons sit inside their pills (29pt icon, number beside it). Hearts and
  gems show a dash until the backend has them.
- Corner buttons, with labels centred: Search and Progress on the left
  (Progress opens Surah Progress), Journey and Review on the right. Journey
  and Review open the new page from Figma `1151:9846`: back arrow, book icon,
  "BUILDING YOUR EXERCISES ....", and a solid bottom bar with the chest
  selected. It lives in `ComingSoonScreen.tsx`.
- Lumo (`lumo_transparent.png`, already shipped) stands left of the very
  first level. Signboards and decor avoid him.
- A "back to my level" arrow (`BackToLevelButton`) appears when the active
  level is off screen, pointing up or down. It is checked only when a scroll
  settles, so there is no per-frame work.
- New art: `back_button`, `icon_building_book`, `nav_home_inactive`,
  `bottom_bar_bg_solid`. The green chest is the existing art with a colour
  swap.

Third pass (user feedback):
- START and JUMP HERE? tags are compact (11pt, about 28pt tall, down from
  Figma's 15pt / 49pt). START sits just clear of the progress ring.
- Every surah's first level shows JUMP HERE? until it's done, not only the
  next surah's. Tapping the tag or the node centres that level and opens its
  start card. Signboard placement reserves room for these tags and for START
  with its ring.
- The path starts at An-Nas level 1, with nothing drawn below it.
- Level counts checked against the backend seeders (read-only):
  `scripts/seed_lesson_groups.py` and `seed_catalog.py` chunk every surah
  into 2-ayah groups, and `seed_special_levels.py` adds a review after every
  pair plus a solo trailing review. That is exactly `buildLevelsWithReviews`,
  so per-surah counts match. Known backend issue (not ours to touch): reads
  cap at 200 groups, so Al-Baqarah's 215 come back truncated.

## New fonts: Nunito ExtraBold, Nunito Black, Inter Bold

Figma uses them, and the user chose to add the exact fonts. They are
single-weight instances made with fontTools from the official Google Fonts
variable files (`ofl/nunito`, `ofl/inter`). Internal names match the existing
`Nunito-Bold.ttf` pattern (PostScript `Nunito-ExtraBold`, `Nunito-Black`,
`Inter-Bold`).

Added to `assets/fonts/`, `android/app/src/main/assets/fonts/` and
`ios/UstadApp/Fonts/`, plus `Info.plist` `UIAppFonts` and `project.pbxproj`
(12 additive lines, same pattern as the existing fonts).

**Needs a native rebuild to show.** Until then text using them falls back
to the system font. The Android release copy at `C:\BuildProjects\ustadapp-mobile\`
needs the three `.ttf` files synced too.

## Known gaps in map2 (by design for now, or awaiting answers)

- No pull-to-refresh (its spinner would sit behind the pinned header). It
  still refreshes on app foreground and after a lesson, through `useMapData`.
- No guided tour on map2.
- A Search pick returns to the old map, because SearchSurahs navigates to
  `MainTabs/Map`.
- While map2 is open, the old map tab is still mounted, so both refresh on
  app foreground (duplicate calls, dev preview only).
- "Next stage" / "Previous stage" pills (chapter paging) are not in the
  Figma. They reuse the START label style.
- The streak card always shows the Figma flame. The frozen-streak icon swap
  from the old HUD is not applied.
