# Changes 2026-10-28

## Small-screen fixes for Apple review (iPad Air 11-inch M3)

The app is iPhone-only (`TARGETED_DEVICE_FAMILY = 1`), so Apple's review iPad runs it in an
iPhone-sized compatibility window of about 375x667pt (iPhone 8/SE size). An audit at that size
(Android emulator resized with `adb shell wm size 750x1334` + `wm density 320`) found four issues.
Everything else fit: all tabs, the map, the lesson exercises, the quit modal and the tour.

### Login and Sign Up: Lumo under the status bar

The content is taller than a 667pt window, so the centred ScrollView starts at y=0 and Lumo's head
sat under the clock and battery. iOS is worse because of the extra Sign in with Apple button.

- `LoginScreen.tsx`, `SignUpScreen.tsx` (email step): the scroll content gets
  `paddingTop: insets.top`. On tall phones this only moves the centred content down by half the
  inset.

### Tour step 18: mic spotlight off to the right

The spotlight hole sat about 40pt right of the mic. The mic lives in an exercise that slides in from
40pt to the right (`ExerciseSlide`, native driver). The native driver moves the real view but never
updates React's own layout tree, which keeps `translateX: 40`; on the new architecture
`measureInWindow` reads that tree, so the mic measured 40pt right even at rest. (A first attempt that
only re-measured after the slide was built and checked: no change, which ruled out timing.)

- `ExerciseSlide.tsx`: once the slide finishes, the transform is dropped from the style so the layout
  tree matches the screen, then the new optional `onSettled` fires. This applies to real lessons too
  (no visible change: the transform is already 0 at that point).
- `useTourTarget.ts`: also returns `measure`.
- `TourLessonScreen.tsx`: re-measures the Check, mic and option targets in `onSettled`. The exercise
  area's `{...exerciseTarget}` spread became explicit `ref`/`onLayout` so `measure` is not passed to
  a View.

### Onboarding name and age: input could end up behind Continue

No ScrollView, so with the keyboard up a 667pt window had about 407pt for about 403pt of content.

- `OnboardUsernameScreen.tsx`, `OnboardAgeScreen.tsx` (+ styles): the middle content is now a
  ScrollView (`scroll: { flex: 1 }`, `content` uses `flexGrow: 1`), footer unchanged.

### Map: Feedback button on top of the Surah sign

For a learner on the first surahs the map rests at its bottom end, so on a short screen the active
surah's sign lands right on the floating Feedback button.

- `map2Model.ts`: `feedbackCoversRestingBoard()` works out, from the real layout, where the map rests
  for the active level (centred, clamped to the map's ends, same as `useMap2Jump`). It returns true
  when that surah's sign is on or within 8pt of Feedback's corner spot. Feedback's Figma numbers moved
  here as `FEEDBACK_W/H/RIGHT/ABOVE_BAR`.
- `Map2FeedbackButton.tsx`: new `inColumn` puts it in the corner column one step under Review
  (lined up with Review's left edge). Otherwise it keeps the Figma corner spot.
- `Map2Screen.tsx`: passes `inColumn`; the "back to my level" lift is skipped in column mode since
  nothing shares the corner then.

Taller phones keep the Figma layout. `tsc` clean, jest 107/107.

## Lesson audio wave sat on the Next / Check button

The playing wave (`AudioWaveBar`) was pinned to the screen bottom (`insets.bottom + 8`), from before the
exercise layout pinned its footer button there, so it drew on top of Check / Got it.

- New `components/lesson/ExerciseWave.tsx`: `ExerciseWaveContext` (true while audio plays on an
  exercise that shows the wave) and `ExerciseWave`, which centres the wave in a given gap with 4pt
  clear above and below. In a tight gap it shrinks (same aspect, full size 220x60); it renders
  nothing only when the gap can't fit a 36pt-tall wave. (A first version hid it below 76pt, which hid
  it on a fill-the-blank with a 72pt gap; changed per "only hide if there is no space".)
- `ExerciseLayout.tsx`: draws `ExerciseWave` in the gap between the content's bottom and the footer,
  using the heights it already measures. Content that fills or scrolls leaves no gap, so the wave
  hides only then.
- `LessonSessionScreen.tsx`: provides the context (same `showWaveBar` rule as before) instead of
  drawing `AudioWaveBar`. The tour and the placement test don't provide it.
- Removed `AudioWaveBar` from `LessonOverlays.tsx` and its two styles from `lesson/styles.ts`.

## audio_fill ("Hear and fill the blank") play circles didn't follow the sound

Tapping an option set it to playing, but `playUrl()` calls `stopAudio()` before it plays, and that
"stopped" event cleared the option straight away, so it showed play while its clip played.

- `AudioFill.tsx`: keeps the option last started plus the real playing state from `onPlayingChange`.
  A circle shows pause exactly while audio is playing and it was the last one started, so it goes
  back to play when the clip ends, is paused or is stopped. "Hear the word" clears the started option.

Not changed: `PlayPauseBtn` (the Listen button) uses the same "clear on stop" pattern and can flip to
idle between words of a sequence. Flagged to the user, left for later.
