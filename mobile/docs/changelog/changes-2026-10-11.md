## Leaderboard: the gold row is always you, and you are always ranked

User: "the highlighted yellow row is always the user himself, and he is
always ranked". Before, "you" was found by display_name match (misfires on
shared names) and a user outside the top 13 did not appear at all.

Backend (local only, not committed or deployed):
- Cache now holds only the shared top rows (with internal `user_id`); the
  caller's own row is read fresh every request (`get_own_row`) and merged by
  XP (`merge_standing`): if they make the top 13 they are slotted in and
  flagged `is_me`, ties placed after equal XP. Unverified callers are merged
  into their own view too (still hidden from everyone else's).
- Outside the top 13: rank = 1 + other verified learners with XP >= theirs
  (`count_ranked_at_or_above`), never below `len(entries) + 1`.
- Response gains `entries[].is_me` and `me` (always present). Backward
  compatible for old app builds. `user_id` is never sent.
- `tests/test_leaderboard_standing.py` (5 tests). pytest 246 passed.

App: `is_me` drives the gold row; when the user is outside the list their
gold row follows a `• • •` break with their real rank. Name match kept only
as fallback for an older backend. tsc clean, jest 54/54.
