# Changes — 2026-10-07

Ships the work logged in `changes-2026-10-05.md` and `changes-2026-10-06.md`,
which had been sitting uncommitted. This entry covers only what changed today
plus the release mechanics.

## Backend switched to production

`src/config.ts` now points at `https://ustad-app-backend-six.vercel.app`
(production) instead of `https://ustad-app-backend-testing.vercel.app`. Done
on the user's explicit instruction, which the standing rule requires — a
"production build" alone never implies this switch.

**Verified before switching**, as asked:

| | production (`six`) | testing |
|---|---|---|
| `/health` | HTTP 200, 0.99 s | HTTP 200, 6.35 s |
| `env` | production | production |
| deployed build | `cb2d195` | `dd4277e` |
| `POST /api/v1/auth/apple` | **422** (route exists) | 422 |
| `POST /api/v1/auth/google` | 422 | 422 |
| audio bucket | identical Supabase URL | identical |
| mongo / supabase / postgres / redis | all configured, no config errors | same |

Two things worth recording:

- **The two deployments are NOT on the same commit.** Production serves
  `cb2d195`, testing serves `dd4277e`, and `cb2d195` does not exist in the
  local backend clone at all, so it was pushed from elsewhere. The user's
  "I made it same now" refers to the environments being equivalent for app
  purposes, not to identical builds.
- **Apple Sign In was confirmed present on production by probing the live
  route**, not inferred from the commit. An empty POST returns 422
  (validation failure, so the route is registered) rather than 404. This
  mattered because the whole point of the current iOS cycle is the Guideline
  4.8 Sign in with Apple rejection, and shipping against a backend without
  that endpoint would have failed review again.

Production also responded roughly 6x faster on a cold `/health`, which is
incidental but welcome given the cold-start latency behind the offline-banner
bug fixed on 2026-10-05.

## Version 1.0.35

`package.json` bumped 1.0.34 to 1.0.35 and `npm run sync-version` propagated
it to `app.json` (`expo.version`) and both `MARKETING_VERSION` entries in the
iOS pbxproj. First real use of the sync script added on 2026-10-05.

Bumped rather than reusing 1.0.34 because 1.0.34 already shipped as iOS build
20042 on 2026-10-03. Reusing it would have meant the in-app notes popup never
firing for anyone who already saw it, and the version label no longer
identifying a build.

## Website: Apple added to the legal pages

Separate repo (`Desktop/Ustaadapp-website/ustad-website`, Next.js).

The privacy policy covered Google sign-in and email/password but said nothing
about Apple, despite Sign in with Apple having shipped in build 20042. Added:

- **Privacy, section 1** — a "Sign in with Apple" paragraph describing the
  identity token, the name and email shared during the flow, and that no Apple
  password is stored. Wording checked against `services/appleAuth.ts:76`
  (`FULL_NAME` and `EMAIL` scopes) rather than guessed. Explicitly covers
  **Hide My Email**: if used, we receive a `privaterelay.appleid.com` relay
  address rather than a personal one, and use it for account contact.
- **Privacy, section 3** — Apple added to the third-party processor list, for
  both authentication and the email relay.
- **Terms, section 3** — Apple named alongside Google as a supported sign-in
  service, plus a new paragraph: third-party sign-in is subject to that
  provider's terms, account access depends on retaining the third-party
  account, and disabling Apple's relay for UstadApp may leave us unable to
  reach the user.
- Effective date on both bumped to October 6, 2026, which each document's own
  "changes" section requires on a material change.

Privacy was committed and merged by the user mid-session (now in `fe42571`
lineage); the terms change is still uncommitted on branch
`fix/hero-cta-sizing` alongside unrelated hero work.
