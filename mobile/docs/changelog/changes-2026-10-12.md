# Changes, 2026-10-12

## "You're offline" banner only when the phone has no network

User (iOS screenshot, 1.0.38): "You're offline. Please come back when you
have a connection." stayed up on a strong connection while the game kept
working.

Cause: `services/connectivity.ts` marked the device offline when netinfo's
`isInternetReachable` was false. On iOS netinfo has no native reachability
(`ios/RNCNetInfo.mm` reports only `isConnected`), so that value came solely
from a JS `HEAD https://clients3.google.com/generate_204` every 60s (15s
timeout, retry every 5s while failing). One failed or slow probe set the
banner, and only a later successful probe cleared it; our own API calls never
touch `isDeviceOffline`, which is why the app kept working underneath. The
file's comment assumed the OS answers, which is true on Android only.
Shipped like this since 1.0.35.

Fix (approved by user): `isOffline()` now reads only the OS's network answer,
`type === 'none' || isConnected === false` (null still means "not yet known",
not offline). The Google probe is switched off with
`NetInfo.configure({ reachabilityShouldRun: () => false })` before the
listener is added, so it no longer costs a request a minute. "Has a network
but can't reach Ustad" stays covered by `isServerUnreachable` from real API
calls (status 0).

Tests: `__tests__/connectivity.test.ts` updated for the new rule (a failed
probe with a network is NOT offline; `isConnected=false` is; `null` is not).
jest 56/56, tsc clean. Not in a build yet (1.0.38 has the old behaviour).
