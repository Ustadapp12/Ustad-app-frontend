# Changes 2026-10-23

## iOS: ITMS-90683 missing location purpose string

App Store Connect warned on build 20057 (1.0.44): `NSLocationAlwaysAndWhenInUseUsageDescription`
missing. Delivery succeeded; it is a warning, but Apple wants it fixed in the next binary.

- `ios/UstadApp/Info.plist`: added `NSLocationAlwaysAndWhenInUseUsageDescription` with the same
  prayer times / qibla string as the existing `NSLocationWhenInUseUsageDescription`.

Why it fired: `@react-native-community/geolocation` links `requestAlwaysAuthorization` in its
native code (`RNCGeolocation.mm`), so Apple's static scan flags it even though we never ask for Always.

Safe because the library's default authorization level only escalates to Always when
`NSLocationAlwaysUsageDescription` (the old iOS 10 key) is present, which we do NOT add. Users still
see the "While Using the App" prompt only. Do not add `NSLocationAlwaysUsageDescription`.

## iOS: full purpose string audit

Scanned the iOS source of every native dependency in package.json for APIs that need a purpose
string (location, mic, camera, photos, contacts, calendar, motion, bluetooth, speech, tracking,
Face ID, local network, health, media library, HomeKit, NFC). Expo native modules are not linked
(the Podfile has no `use_expo_modules!`).

| Library | API found | Info.plist key | Status |
|---|---|---|---|
| @react-native-community/geolocation | CLLocationManager, requestAlways/WhenInUse | NSLocationWhenInUse + NSLocationAlwaysAndWhenInUse | covered |
| react-native-compass-heading | CLLocationManager, requestWhenInUse | NSLocationWhenInUseUsageDescription | covered |
| react-native-audio-recorder-player | requestRecordPermission | NSMicrophoneUsageDescription | covered |
| react-native-keychain | LAContext (Face ID) | NSFaceIDUsageDescription | added today |

- `ios/UstadApp/Info.plist`: added `NSFaceIDUsageDescription`. Never shown in practice:
  `secureTokens.ts` stores with `WHEN_UNLOCKED_THIS_DEVICE_ONLY` and no `accessControl`, so no
  biometric prompt runs. Added so a future biometric option can't crash on a missing key.
- Nothing else found. No ATT string needed: `$RNFirebaseAnalyticsWithoutAdIdSupport = true` keeps
  the IDFA out, consistent with `NSPrivacyTracking = false`.
- `PrivacyInfo.xcprivacy` already declares precise location (on-device, not linked) and audio data.
- Both build configs use `INFOPLIST_FILE = UstadApp/Info.plist`; nothing regenerates it.
- Limit: Firebase/GoogleAppMeasurement ship as precompiled binaries, so they were not
  source-scanned. They raised no ITMS-90683 warning on 20057, and that warning is the binary-level check.

## Search: bigger JUMP HERE arrows

- `src/screens/home/SearchSurahsScreen.styles.ts`: `jumpArrows` font size sc(11) to sc(18), so the
  `▸▸` arrows reach the height of the JUMP HERE capitals (sc(13) Nunito Black). The `▸` character
  draws at about half its font size, which is why it needs the bigger number. Not yet checked on a device.

## Privacy manifest: location is linked, not on-device only

`PrivacyInfo.xcprivacy` said precise location was never sent to the backend (Linked = false). Wrong:
`screens/pray/prayerData.ts` sends every Pray tab fix to `/users/me/location`, and
`services/usageSession.ts` attaches the last fix to each usage session start, both with the bearer
token. Now Linked = true, purposes App Functionality + Analytics, Tracking still false. The App Store
Connect App Privacy answers must match (Precise Location, linked, not tracking).
