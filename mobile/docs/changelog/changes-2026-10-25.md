# Changes 2026-10-25

## Status bar icons follow the screen (dark screen = white icons)

Problem: the app never set a default status bar style. Android uses `Theme.AppCompat.DayNight`
and iOS does not lock the style, so on a phone in dark mode the clock, wifi and battery icons
turned white over our light screens and disappeared.

- New `src/hooks/useStatusBarStyle.ts`: `useStatusBarStyle('light' | 'dark')`. Sets the style
  while the screen is focused and resets it to the default (dark icons) when the screen is left.
  Light screens need no call. No new library, it is the built in React Native `StatusBar`.
- `App.tsx`: sets dark icons once at startup so the phone's dark mode can never override it.
- White icons (`'light'`) on the dark screens:
  - `SplashScreen` (WorldLoading, `#0D1B2A`)
  - `PrayScreen` (hero card behind the status bar; its old inline focus effect replaced by the hook)
  - `DailyQuestScreen` (green gradient; guests see the light GuestGate, so it stays dark there)
  - `StreakCelebrationScreen`, `StreakRepairProgressScreen`, `LessonSummaryScreen` (green gradient)
  - `Map2Screen` only while the dark WorldLoading overlay shows (sky and slow loader are light)
  - `LessonSessionScreen` only while the dark Bismillah intro shows
  - `ErrorBoundary` (dark error screen, outside the navigator, so it sets the style directly and
    restores the default on "Try again")

Not built yet. Check on a real device with the phone in both light and dark mode.

## Back arrow colour

- `src/components/BackButton.tsx`: arrow tint changed from charcoal (`colors.darkText`) to the
  light grey `#AFAFAF`, the same grey as the map's locked-node lock icon (`map2/art/IconLockArt`).
  Every back arrow in the app (17 screens) goes through this component, so all of them change.

## Map: new level and Lumo show faster after a lesson

Problem: after a level, the map only started reloading once the user tapped Continue, then made
up to 3 server calls one after the other (recommended next, then that surah's levels, then the
left surah's levels). The new level and Lumo appeared a few seconds late.

- New `src/services/mapReturnRefresh.ts`: loads "recommended next" and the left surah's levels at
  the same time, plus the recommended surah's levels only when it moved to a new surah. Usually one
  round trip instead of three in a row (option B).
- `store/lessonStore.ts` `completeSession`: starts that load as soon as the completion is saved,
  while Lesson Complete is still on screen (option A). Not done for abandon (no screen to hide it
  behind); abandon still gets the parallel load.
- `screens/home/map/useMapData.ts` focus refresh: uses the preloaded result (or loads it now),
  and applies both surahs in one state update so the level and Lumo appear together. Same flag
  clearing and SURAH_COMPLETE analytics as before. Still fully server driven, nothing guessed.

Not built yet. Test: finish a level (Lumo should move almost at once), finish a surah's last level
(next surah unlocks, old one turns gold), and exit a level early.

## Pray tab: tiny clock on iPhone, clock lag, "NEXT :" spacing

From a user feedback screenshot (build unknown).
- `HeroSalahCard.tsx`: the clock had `adjustsFontSizeToFit` with a `lineHeight` below Nunito Black's
  natural height, so iOS decided it never fit and shrank it to a few points (drawn tiny, off to the
  left). Removed; `sc(60)` already sizes it to the screen width. Same flag removed from the button
  label (fixed size button, label fits, same iOS risk).
- Clock now updates on the exact minute boundary (was every 15s, so up to 15s behind the phone).
  Still focus scoped.
- `DateRow.tsx`: "NEXT : FAJR" to "NEXT: FAJR".
- The screenshot's light strip under the status bar, cut off Log Salah button and empty gap below
  the card are the iOS gradient bug fixed on 2026-10-22 (`GradientBox`, build 20058 and later).
  Rechecked: `HeroSalahCard` still uses `GradientBox`, padding sits on the View, gradient is an
  absolute fill. So the screenshot is from an older build, or needs a device check on 20060+.

tsc clean, eslint clean on both files, jest 105/105. Not built.

## Supervisor review follow ups (A-6, A-7, dead code)

- `utils/responsive.ts` (A-6): `useResponsiveScale()` returned a new function every render, so every
  `useMemo(() => makeStyles(sc), [sc])` (about 30 files) rebuilt on every render. Now
  `useCallback` keyed on the scale: same function until the window width changes.
- `services/localNotifications.ts` (A-7): `refreshLocalNotifications` ran six native
  cancel/schedule calls on every 60s learning poll. Now skipped when streak, prefs and local day
  match the last run and that run is under 30 min old. The 30 min cap keeps `inactivity_nudge`
  (24h after the latest refresh) moving while the app is in use, with at most 30 min drift.
  Lesson completion changes the streak/date inputs, so it always reschedules.
- Dead code removed: `hooks/useAbandonLessonOnBackground.ts` (never imported) and
  `services/audioUrls.ts` (an empty `warmAudioUrlCache()`), plus its import and call in
  `authStore.ts`.
- Audio preloading (A-11) left as is: it is used. Every clip of the lesson is loaded into a player
  when the lesson opens, so audio plays instantly; playback reads from that cache.

tsc clean, eslint 0 errors, jest 105/105. Not built.

## Supervisor review audit (agent)

Every finding of the 28 Sep performance review (M-1 to M-14, A-1 to A-19, section 5) checked
against the current code. Fixes below are JS/TS only, with no visible change.

- `screens/leaderboard/LeaderboardScreen.tsx` (review 5.7 #4): the first open fired the same
  leaderboard request twice (a mount `useEffect` plus `useFocusEffect`). The mount effect is
  removed; the focus effect covers the first open, and `loading` already starts true so the
  spinner shows exactly as before.
- `screens/home/map/useMapData.ts` (M-11): the map's foreground refresh (3 server calls) ran even
  when the map was hidden (inside a lesson, on another tab). Now it runs only while the map is
  focused; otherwise it is marked as due and runs the moment the map is shown again, so the map
  never stays on pre-background data.
- `screens/home/map2/Map2Screen.tsx` (M-9): the legacy model used for the level card styles was
  rebuilt (including its decoration placement search) whenever the window height changed. Now
  keyed on width only. Height only feeds the old map's sky line, grass edge, clouds and birds,
  which map2 never reads, so the output is identical.
- `screens/home/map/components/LoadingBar.tsx` + `Map2Screen.tsx` (M-14): removed the unused
  `nodesReady` prop.
- New `utils/countUp.ts`, used by `LessonSummaryScreen.tsx` and `StreakCelebrationScreen.tsx`
  (A-10, 5.5 #1, 5.6 #1): the XP and streak count ups now update the number at most every 100ms
  (about 10 renders a second instead of up to 60), and the final total always lands at once.
  Test: `__tests__/countUp.test.ts`.
- `services/audioPlayer.ts` (A-3, 5.2 #1): the correct/wrong chimes are no longer loaded at app
  start (two native players before the first screen). New `preloadFeedbackSounds()` is called on
  mount by `LessonSessionScreen`, `LessonSummaryScreen` and `VerifyEmailScreen`, well before
  their first ding. If a ding ever beats the load, it plays once the load finishes instead of
  being dropped.
- `services/bootCache.ts` (A-4): `prefetchAll()` no longer calls `authApi.me()` a second time
  at boot. Its only effect was filling a profile cache that nothing read (`getCachedProfile` /
  `setCachedProfile` had no callers); that dead cache is removed too.
- `screens/home/SearchSurahsScreen.tsx` (5.4 #1): the style sheet memo was keyed on a fresh insets
  object, so it rebuilt on every keystroke. Now keyed on the bottom inset number.
- `screens/auth/VerifyEmailScreen.tsx` (5.2 #2): `startCooldown()` clears any earlier timer
  before starting a new one.
- `screens/help/HelpScreen.tsx` (5.9): removed the unused `lumaAnim` prop from `FaqCard`.

Not changed on purpose (needs the user, or outside JS): splash 1s minimum, audio preloading,
notification timing, LoadingBar / progress bars / TourOverlay fade on the native driver (not
provably identical), adjustsFontSizeToFit on map2's stat card and surah board (visual), and
everything in package.json, android/, ios/, .github/ and the backend.

Verification: `tsc --noEmit` clean. eslint on the 14 changed files: 15 errors, all already there
before (16 before; the HelpScreen unused var is gone), no new ones. jest 107/107 (105 plus the 2
new count up tests). Not built. Test on device: the XP and streak count up on Lesson Complete and
the streak celebration, the first correct/wrong ding in a lesson, the "verified" ding, and
backgrounding the app inside a lesson, then returning to the map (it should refresh).
