# Changes log — 2026-08-10 session

Analytics instrumentation, first slice of the beta-testing backlog (Firebase
Analytics side). Backend counterpart (`app/usage/router.py`,
`usage_sessions` table) is tracked in `ustadAppBackend/CHANGES.md`.

## 1. `surah_completed` event — `src/services/analytics.ts`, `src/screens/home/MapScreen.tsx`

- Added `SURAH_COMPLETE: 'surah_completed'` to the `AnalyticsEvents` registry.
- Fired from the existing focus-effect in `MapScreen.tsx` that already
  re-fetches `learningApi.levels(completedSurah)` when the just-finished
  surah differs from the newly-recommended one (i.e. finishing a level
  advanced "recommended next" to a different surah). Checks
  `completedLevels.every(l => l.status === 'completed')` off that same
  fetch — no new network call. Robust to however many review/special levels
  a surah actually has (interleaved or trailing), since it only reads
  `status`, not level count or `is_special`.

## 2. `screen_view` auto-tracking — `src/navigation/RootNavigator.tsx`

- `logScreenView()` has existed in `analytics.ts` since Firebase Analytics
  shipped, but nothing ever called it — `docs/FIREBASE_ANALYTICS.md`
  documented it as working when it wasn't.
- Added `onReady`/`onStateChange` on `NavigationContainer`, tracking
  `navigationRef.getCurrentRoute()?.name` (resolves through nested
  navigators, e.g. `MainTabs`' bottom tabs) and firing only on an actual
  route-name change.

## 3. App-usage session envelope — new `src/services/usageSession.ts`, `src/api/index.ts` (`usageApi`), `App.tsx`

- `usageApi.startSession` / `endSession` call the new backend
  `/usage/sessions` endpoints.
- `services/usageSession.ts`: thin wrapper holding the in-flight session id,
  best-effort (failures are swallowed — analytics must never affect the
  lesson experience).
- `App.tsx`:
  - New effect starts a session the moment a user exists (covers cold-start
    `hydrate()` and fresh login/register/guest), via
    `useAuthStore.subscribe((state, prev) => ...)` edge-detecting
    `user`/`!user` transitions; ends one on logout.
  - Reuses the *existing* 60s "really backgrounded" grace timer (the one
    that already decides when to abandon an in-progress lesson) to end a
    session — a quick app-switcher glance or a permission dialog doesn't
    fragment one sitting into several rows. Starts a fresh session on the
    matching "wasBackgrounded → active" return.
- `__tests__/App.test.tsx`: the existing `authStore` mock only stubbed
  `getState`; added a no-op `subscribe` stub so the new effect doesn't throw
  in the test environment (real zustand v5 stores have `.subscribe` — this
  was a gap in the mock, not in the store).
- New `__tests__/usageSession.test.ts` (6 tests): start/end call the right
  `usageApi` methods with the right args, a second `start` while one's
  already active is a no-op, ending clears state so a new session can start,
  and both start/end swallow API failures without throwing. Needed an
  `afterEach` calling `endUsageSession()` — the service's "active session"
  state is deliberately module-scoped (one real session per app lifetime),
  which otherwise leaks across test cases in the same file.

## 4. iOS build + TestFlight submission — new `.github/workflows/ios-testflight.yml`, `eas.json`, `.gitignore`

- New workflow (repo root, alongside `firebase-distribution.yml`): `eas build
  --profile production` (store distribution — required for TestFlight;
  `preview`'s `distribution: internal` would produce an ad-hoc build that
  can't be submitted) then `eas submit --profile production --latest`.
- `workflow_dispatch` only for now — deliberately not wired to push/merge
  like the Android job, since it can't succeed until the manual prerequisites
  below exist. Flip the trigger once a run has gone green.
- Apple credentials for `eas submit` (App Store Connect API key) are passed
  as env vars (`EXPO_ASC_API_KEY_PATH` / `_KEY_ID` / `_ISSUER_ID`) rather than
  committed to `eas.json`, matching how Android's secrets are injected at
  CI-runtime rather than checked in. `eas.json`'s `submit.production.ios` is
  left as `{}` for that reason.
- `eas build`'s own Apple signing (distribution cert + provisioning profile)
  is a separate credential set, managed remotely by EAS — set up once via an
  interactive `eas credentials` run, not part of this file.
- Added `*.p8` to `.gitignore` — the downloaded App Store Connect key must
  never be committed.
- **Requires 5 new GitHub secrets** (`EXPO_TOKEN`, `GOOGLE_SERVICE_INFO_PLIST`,
  `ASC_API_KEY_P8`, `ASC_API_KEY_ID`, `ASC_API_ISSUER_ID`) and the manual
  Apple/Firebase/App-Store-Connect setup listed in the workflow file's header
  comment — none of that can be done from here. Untested until those exist.
