# Changes 2026-09-06

## Lesson session resume — progress no longer lost when the app is killed/reopened mid-level

**Platform:** Both Android and iOS. Requires the matching backend fix (logged in the backend
repo's own `CHANGES.md`, 2026-09-06) — this is the client half of one combined fix.

**Bug:** closing the app (or it getting killed) partway through a level, then reopening it,
answering the exercise shown, and having the level immediately end at 0% accuracy / 0 XP / 0
time — even though most of the level had already been answered correctly before the
interruption.

- `store/lessonStore.ts` — `startSession()` no longer calls `abandonPendingLessonSessionFromStorage()`
  before asking the backend to start a session. That call was unconditionally abandoning any
  existing in-progress session first, which destroyed the very session the backend's new resume
  logic is meant to reconnect to. Added `resumed`, `sessionStartedAt`, `xpEarnedSoFar` to
  `LessonState`; `mistakes`/`correctCount` are now seeded from the response's
  `hearts_lost_half`/`correct_count` (previously always hardcoded to 0 on every start).
  Switching to a *different* group, or an explicit quit (✕ → confirm), still abandon exactly as
  before — only reopening the same in-progress level now resumes.
- `screens/lesson/LessonSessionScreen.tsx` — the mount-time seeding effect (fires once
  `firstExercise` arrives) now branches on `storeResumed`: on a resume it seeds local
  `correctCount`, `mistakes`, `totalXpRef.current`, and `sessionStartedAtRef.current` from the
  store instead of leaving them at their fresh-mount defaults, and skips the "Begin Lesson"
  Bismillah splash (this isn't actually the start of the level). On a genuinely fresh session
  behavior is unchanged.
- **Also fixed in the same effect:** the app can die in the gap between hearts hitting 0 and the
  user tapping through the "Out of Hearts" modal (whose "Retry Level" button is what actually
  calls `abandonSession`) — that left the session resumable instead of ended, so reopening would
  silently let play continue past the heart limit. The resume branch now re-checks
  `storeMistakes >= MAX_MISTAKES` (the same constant `submitAnswer` uses) and shows the existing
  "Out of Hearts" modal immediately instead of seeding the user into a live exercise — reuses the
  already-wired modal/`abandonSession` flow, no new UI.
- `types/api.ts` — `LessonSessionStart` gets four new optional fields matching the backend's
  `StartSessionOut`: `resumed`, `started_at`, `xp_earned_so_far`, `hearts_lost_half`.

**Verified:** `npx tsc --noEmit` clean on the whole project after each edit. Not yet verified by
hand on a device/simulator (force-kill mid-level → reopen, both the ordinary-resume path and the
hearts-already-exhausted path) — no `adb`/emulator/e2e tooling available in this environment to
drive that automatically.

**Not committed as of 2026-09-06.**

## `config.ts` — backend URL switched from testing to production

**Platform:** Both. Config-only, no code logic changed.

- `PRODUCTION_API_BASE` now points at `https://ustad-app-backend-six.vercel.app` (the real
  production backend); the testing URL (`ustad-app-backend-testing.vercel.app`) is commented out
  instead of active. Done on explicit request. Confirmed reachable: `/health` returns
  `"status":"ok"` with Mongo/Postgres/Redis/Supabase all configured, build `b2130cd`.
- **Consequence:** any manual testing done against a build using this config (including the
  resume/hearts-exhaustion checks above) now writes real completion rows, XP, gems, and streak
  data to production — not the testing database.
