# Changes 2026-10-03

## Added: Sign in with Apple (iOS only), for App Review Guideline 4.8

**Report:** first App Store submission rejected under Guideline 4.8 (Login
Services). The app offers Google Sign-In, and Apple requires an equivalent
privacy-focused option (in practice, Sign in with Apple) whenever a
third-party login is offered.

**What was added:**
- `@invertase/react-native-apple-authentication@^2.5.1` (iOS native module;
  Android untouched, the button renders nothing there).
- `src/services/appleAuth.ts`: native half only, same rules as
  `googleAuth.ts` (lazy require, cancel returns null, user-safe errors). Lets
  the library generate a nonce and forwards the raw value, identity token,
  authorization code, and the name (Apple only sends the name on the first
  authorization).
- `src/components/AppleSignInButton.tsx`: custom black HIG-style button (Apple
  logo, system font, approved wording only). Deliberately not the library's
  native `AppleButton`, which is a legacy `requireNativeComponent` view.
  Renders `null` unless `appleAuth.isSupported` (iOS 13+).
- `authStore.loginWithApple()` + `authApi.apple()` -> `POST /auth/apple`.
  The post-response logic of `loginWithGoogle()` was extracted into
  `completeSocialSignIn(res, provider)` so both providers share the exact same
  guest/tour/analytics/onboarding rules. No behaviour change for Google.
- Entry methods `apple_login` / `apple_signup` added to both `EntryMethod`
  unions (backend stores it as free text, no backend change needed).
- `LoginScreen` / `SignUpScreen`: Apple button placed above Google, same size.
  On SignUp it is gated on the terms checkbox exactly like Google.
- `ios/UstadApp/UstadApp.entitlements` (new) with
  `com.apple.developer.applesignin = [Default]`, wired via
  `CODE_SIGN_ENTITLEMENTS` in both Debug and Release of `project.pbxproj`.
- `jest.setup.js`: mock for the new native module.

**Not shippable until:** the Sign in with Apple capability is enabled on the
`com.ustadapp` App ID and the App Store provisioning profile is regenerated
and re-uploaded to the `IOS_PROVISIONING_PROFILE` secret. Without that, the
iOS build fails at signing (profile lacks the entitlement). Backend must also
be deployed with `POST /auth/apple` first (see backend `docs/APPLE_SIGNIN.md`).

## Performance Phase 1, step A: cold start, bundle and release hygiene

All five from the merged Phase 1 "free wins" in `thingstodo.md`. Backend URL
deliberately untouched: `config.ts` stays on `ustad-app-backend-testing`.

- **`babel.config.js`**: added `env.production.plugins:
  ['transform-remove-console']`. The dependency was already in
  `devDependencies` but had never been wired, so 45 `console.*` calls were
  shipping in release bundles. Scoped to the production env so Metro dev and
  jest keep their logging.
- **New `src/components/tour/tourGlow.ts`**: `TOUR_GLOW`, `TOUR_GLOW_ROUND`
  and `TOUR_GLOW_ROUND_THIN` moved out of `LessonSessionScreen.tsx`.
  `MainTabs`, `MapScreen` and `MapScreenV2` all imported `TOUR_GLOW`, and that
  one named-constant import was pulling the whole 179 KB lesson screen into
  the tab bundle at splash. Three import edges removed, values byte-identical.
- **`RootNavigator.tsx`**: `MapScreenV2` is no longer a static import. It is
  now `__DEV__ ? require(...).default : null`, and its `Stack.Screen` is
  wrapped in `{__DEV__ && MapScreenV2 && (...)}`. Previously 188 KB of WIP
  module body was evaluated at bundle init on every cold start, including
  release builds where the only door into it (MainTabs' `__DEV__` "V2"
  button) never renders.
- **`renderMode="SOFTWARE"` removed** from all 12 `LottieView` call sites
  across `StreakCelebrationScreen`, `StreakScreen`, `LessonSessionScreen`
  (8 of them), `LessonSummaryScreen` and `ProfileScreen`. These were forcing
  CPU rendering of every Lottie.
- **`index.js`**: `enableFreeze(true)` from `react-native-screens`, called
  after `initCrashReporting()` and before `AppRegistry.registerComponent`. It
  was absent from the whole codebase. Must run before any navigator mounts,
  hence index.js rather than App.tsx.

## Fixed: animations that never stopped

Audited all 18 `Animated.loop` sites and every looping `LottieView`. Two had
no `.stop()` at all; three more stopped only on unmount, which never happens
on a tab screen.

- **`MapScreen.tsx` / `MapScreenV2.tsx`**: the completed-node gold pulse
  (`goldAnim`) was a bare `useEffect(..., [])` that started an endless
  `Animated.loop` and never stopped it, so it kept driving frames while the
  user sat on Quests, Leaderboard or Profile and on every screen pushed above
  the map. Converted to `useFocusEffect(useCallback(...))`; the blur path
  calls `loop.stop()` and parks the value at 0 so nodes return to resting
  size rather than freezing mid-pulse.
- **`DailyQuestScreen.tsx` / `LeaderboardScreen.tsx`**: the Lumo bob
  (`floatAnim`) had correct `return () => loop.stop()` cleanup, but both are
  tab screens that stay mounted for the life of the app, so that cleanup
  effectively never ran. Both converted to `useFocusEffect`. DailyQuest's
  `useEffect` import was replaced with `useCallback` + `useFocusEffect`.
- **`ProfileScreen.tsx`**: the streak flame is an `autoPlay loop` Lottie on a
  tab screen and ran continuously in the background. Added `useIsFocused` plus
  a `LottieView` ref, pausing on blur and resuming on focus. The view stays
  mounted so the stat row does not reflow on tab switch.

Verified as correct and left alone: the other 13 `Animated.loop` sites
(`GuestGate`, `LoadingSpinner`, `LumoInfoModal`, `StreakRepairProgress`,
`StreakScreen`, `HelpScreen`, `SplashScreen`, both map parallax loops,
`LessonSessionScreen` x2) all stop on unmount and live on screens that
genuinely unmount.

## Changed: asset compression (14 MB -> 5.8 MB)

Re-encoded 64 PNGs in place with sharp (`compressionLevel 9`, `effort 10`,
palette quantization where it beat lossless). 9.65 MB -> 2.02 MB of PNG, and
`assets/` overall from about 14 MB to 5.8 MB. No file was written if the
optimized version came out larger.

- **`clouds.png` resized 1988x1290 -> 600x389.** The only dimension change.
  It renders at `sc(110 + hash*70)` wide, i.e. 110-180 dp, so the source was
  roughly 3.7x oversized even at 3x density. Aspect preserved to three
  decimals (0.649 -> 0.648), and it is drawn with `resizeMode="contain"` into
  an explicit box, so the letterboxing is unchanged. 1290 KB -> 37 KB.
- **`mountains_crop.png` deliberately skipped.** `MapScreen.tsx:103-105`
  derives `MOUNTAINS_PAD_FRACTION` as `40 / s.height` from
  `Image.resolveAssetSource` at runtime, so changing its pixel height would
  silently change the rendered skirt that hides the sky seam above the grass.
  Confirmed unmodified.
- Every other image kept its exact dimensions, so the hardcoded aspect ratios
  (`NEXT_STAGE_ASPECT`, `PREVIOUS_STAGE_ASPECT`, `SEASON_GATE_ASPECT`) are
  unaffected.

**Fidelity check:** compared every sampled image against its original per
channel, ignoring fully transparent pixels (where RGB is invisible and
inflates a naive diff). Visible RGB error is a mean of 0.38 to 2.32 out of
255, under 1%, with alpha error between 0.05 and 0.35. A naive whole-image
diff reports a misleading mean of 22-38 purely from RGB noise under alpha=0.

## Added: UstadApp logo in the Profile top left

- **`assets/map/logo_app.png` trimmed and resized**, 600x600 -> 400x142,
  19 KB -> 13.6 KB. The source was a wordmark floating in a mostly empty
  square: only 9.8% of its pixels were opaque, with the real content confined
  to a 532x189 box at x36-567, y170-358. Rendered square it would have come
  out tiny, so it is now cropped to its own content bounds.
- **`ProfileScreen.tsx`**: added a `brandBar` above the `ScrollView` (so it
  stays put while content scrolls), left-aligned with `alignSelf:
  'flex-start'` so it hugs the logo instead of spanning the screen.

**Why it sits on a green pill rather than bare:** the logo is a white
wordmark — 60% of its opaque pixels are pure white, mean luminance 241.8/255.
The Profile background is `colors.lightBg` (#F2F4F8). White on that is a
contrast ratio of **1.03:1**, i.e. invisible. On `colors.primary` (#2A7D4F)
it is **4.72:1**. Tinting was rejected because the mark is not monochrome: the
kufi cap is cream with a tan mosque motif and the eyes are grey, so a
`tintColor` would flatten all of it to one colour. `brandLogo`'s height is
derived as `sc(104) / 2.817` from the asset's own aspect so it can never
squash.
